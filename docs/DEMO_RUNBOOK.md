# PathPilot Live Demonstration Runbook

This runbook is for the Ubuntu 22.04 Mininet VM used by the project. The live demonstration uses Ryu + OpenFlow 1.3 + Open vSwitch + Mininet; it is an emulated network deployment, not a physical production deployment.

## Prerequisites

- Ubuntu VM with Mininet and Open vSwitch installed and running.
- Project virtual environment at `.venv` with Ryu 4.34 and project requirements.
- Run commands from the repository root.
- Use two terminals. Do not run a second Mininet topology while another one is active.

## Terminal 1 — Ryu controller

```bash
cd ~/PathPilot
source .venv/bin/activate
PYTHONPATH="$PWD" EVENTLET_NO_GREENDNS=yes ryu-manager controller/ryu_app.py
```

For another policy, set `PATHPILOT_POLICY` before `ryu-manager`. Current supported policies are listed in the README and controller code.

Wait for the switches to connect and for the controller to log that live telemetry is ready.

## Terminal 2 — Mininet

```bash
cd ~/PathPilot
sudo env PYTHONPATH=/home/pathpilot/PathPilot /usr/bin/python3 topology/mininet_topology.py --controller 127.0.0.1 --port 6653
```

At the Mininet prompt:

```text
mininet> nodes
mininet> net
mininet> pingall
mininet> links
```

The connectivity check should report no packet loss before traffic tests.

## Demonstrate path selection

Use the experiment runner for controlled path selection and goodput experiments. The runner starts and stops its own controller and topology; stop the manually started controller/topology before running it.

Example small smoke test (one trial per policy, baseline telemetry):

```bash
cd ~/PathPilot
source .venv/bin/activate
sudo env PYTHONPATH=/home/pathpilot/PathPilot /usr/bin/python3 experiments/run_balanced_path_matrix.py \
  --trials 1 --conditions baseline --output-dir results/demo_smoke
```

This produces a compact reproducible CSV/report bundle. It is a smoke test, not a substitute for the full final evaluation.

## Clean up

At the Mininet prompt:

```text
mininet> exit
```

Stop Ryu with Ctrl+C. If a previous run left OVS state behind, inspect it before cleaning; do not indiscriminately delete unrelated host bridges.

## Evidence checklist for the final presentation

- Show the topology and the two alternative paths.
- Show Ryu switch connections and live OpenFlow port-stat telemetry.
- Show successful host-to-host connectivity.
- Generate traffic and show a policy decision in the controller log.
- Demonstrate a controlled bottleneck and a subsequent new-flow decision.
- Show the raw CSV and summary generated by the run.
- State clearly that the results are Mininet/OVS emulation results.
- Do not present p99 latency, fairness, packet-loss, or stability claims until the corresponding measurements have been implemented and run.
